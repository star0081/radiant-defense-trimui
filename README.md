# Radiant Defense на TrimUI Smart Pro

Порт [Radiant Defense](https://hexage.net/) (Hexage, движок Monkey/Mojo, версия 2.3.15) на TrimUI Smart Pro со стоковой прошивкой. Прошивку менять не нужно.

В этом репозитории только обвязка: загрузчик, Java-заглушки Android и нативная библиотека, которая рисует кадр, читает геймпад и играет звук. APK, dex, ресурсы и оригинальный `libmojo.so` сюда не входят. Игра остаётся у Hexage, для запуска нужна своя копия.

## На чём это работает

Проверено на TrimUI Smart Pro 1.1.1:

| | |
| --- | --- |
| Процессор | Allwinner A133, Cortex-A53, aarch64 |
| Графика | PowerVR GE8300, OpenGL ES 2.0 |
| Экран | 1280×720 |
| Память | 1 ГБ |
| libc | glibc 2.17 |
| Система | сток, без смены прошивки и без `fbset` |

Карта памяти устроена так же, как у остальных портов на этой приставке:

- меню Ports запускает `Roms/PORTS/Radiant Defense.sh`
- файлы игры лежат в `Data/ports/radiantdefense/`

На устройстве нет bash, `tee` и символических ссылок на FAT32. Скрипт запуска — обычный POSIX `sh` с переводами строк LF. Системные SDL2 и PowerVR берутся из `/usr/trimui/lib`, их нет на карте.

## Обвязка

Игра — это Java-приложение. OpenGL она вызывает из `android.opengl.GLES20`. 64-битная JVM сама открывает системный `libGLESv2.so`, так что отдельный мост к драйверу, которым пользуются порты нативных `.so`, здесь не нужен.

```
Ports
  └─ Radiant Defense.sh
       └─ Temurin JRE 8, aarch64, glibc 2.17
            ├─ shim.jar      заглушки Android, стоят в classpath первыми
            ├─ radiant.jar   игра, собранная из своего APK через dex2jar
            └─ libmojo.so    окно SDL2, GLES, картинки, звук, геометрия
```

`port.Main` поднимает активность в том порядке, которого ждёт движок: `onCreate`, `onStart`, `onResume`, и только потом поверхность 1280×720. Игровой цикл после этого крутится на GL-потоке, около 30 кадров в секунду.

`Build.VERSION.SDK_INT` сообщается как 21, модель устройства — `TrimUI`. При таком SDK движок выбирает простой GL-поток `mojo.am`.

Запуск идёт с `-Xverify:none`. У jar после dex2jar нет таблиц `StackMapTable`, и обычная проверка байткода Java 8 его отвергает.

### Java

`port/tools/gen_stubs.py` читает APK и дописывает недостающие классы Android. Почти каждый такой метод проваливается в `port.Sys.call`, а оттуда уже в осмысленное поведение: файлы, сенсоры, разрешения, коллекции. Интерфейсы получают отдельные реализации, чтобы игра могла их создать.

Отдельно, уже руками, написано то, что заглушкой не закрывается:

- EGL 1.0 поверх SDL: выбор конфига, контекст ES 2.0, окно и `eglSwapBuffers`
- касания и кнопки
- офлайн-клиент Google Play, чтобы меню не ждало сервер, которого на приставке нет

`shim.jar` стоит в classpath раньше `radiant.jar`, поэтому наши классы перекрывают одноимённые из игры там, где это нужно.

### Нативная библиотека

`libmojo.so` собирается Zig в `aarch64-linux-gnu` с потолком glibc 2.17. Она подменяет маленький нативный помощник движка и добавляет то, чего на Android делала система:

- окно и геймпад через SDL2
- PNG через [stb_image](https://github.com/nothings/stb) (public domain)
- Ogg Vorbis через stb_vorbis (public domain) и микшер SDL
- геометрию с тем же контрактом, что у оригинальной ARM-библиотеки

Картинки, которые в APK лежат без сжатия, открываются как кусок zip-файла: смещение и длина записи, затем `stb_image`. Сжатые записи читаются через обычный поток.

### Управление

Курсор для башен, потому что тачскрин здесь заменён геймпадом:

| | |
| --- | --- |
| Select | показать или спрятать курсор |
| Левый стик | двигать курсор |
| L или R | нажатие |
| Start + Select | выйти в Ports |

Подписи на корпусе и номера кнопок SDL расходятся. Правая кнопка подписана A и подтверждает, нижняя подписана B и возвращает назад. Select, Start и плечевые остаются за курсором, кликом и выходом.

## Сложности и как они закрыты

**Чёрный треугольник на заставке.** Квады движок рисует лентой из четырёх вершин. Порядок должен быть левый-верх, правый-верх, левый-низ, правый-низ. Другой порядок оставляет половину прямоугольника пустой.

**Вылет сразу после меню.** Проверка подписи Google Play внутри JVM даёт обычный null-check, а HotSpot реализует его через SIGSEGV. SDL перехватывал этот сигнал и ронял процесс. Перед `SDL_Init` ставится `SDL_NO_SIGNAL_HANDLERS=1`, а класс проверки подписи заменён заглушкой, которая ничего не делает.

**Меню замирает на любом пункте.** На этой приставке правая кнопка для SDL — это «назад», и игра выходила из GL-потока. Поверх этого `GoogleApiClient.build()` ждал сообщение в `Handler`, которое никто не доставлял. Кнопки разведены по подписям на корпусе, сообщения обработчика выполняются сразу, а вместо настоящего клиента Play подставлен офлайн-клиент: соединение не устанавливается, меню идёт дальше.

**С курсором пропадают выстрелы, радиус и туман.** Игра помнит режим смешивания у себя и не зовёт `glBlendFunc`, пока он не изменился. Выстрелы и туман рисуются с заранее умноженной альфой: яркость сидит в RGB, альфа часто нулевая. Первый кадр курсора оставлял после себя другое смешивание и чужой вершинный атрибут, и следующий кадр игры рисовал уже в этом состоянии. Курсор теперь перед рисованием запоминает программу, буфер, вьюпорт, смешивание и атрибут 0, а после кадра возвращает их обратно. Сам курсор режим смешивания не переключает.

**На второй волне пушка стреляет через врага.** Спрайты лежат в одном буфере подряд. Граница столкновения считается нативом `Bounds`: номер вершины умножается на шаг вершины. В первой версии номер подставлялся как смещение в байтах. У первого спрайта в пачке коробка совпадала с картинкой, у следующих уезжала в сторону. Башня поворачивалась по координатам сущности, а попадание искало пересечение с коробкой и не находило его.

**Тишина.** Эффекты — моно 22050, музыка — стерео 44100. Оба лежат в APK как Ogg без сжатия zip. Эффекты разбираются в PCM при загрузке, музыка читается по ходу в кольцо. Громкость 0…100 переводится в амплитуду той же кривой, что в оригинале: `10^(громкость/40 − 2.5)`. Устройство открывается через SDL со звуковым драйвером ALSA, как у соседних портов. Шестнадцать голосов, как было в OpenSL.

**Купленные пакеты не находятся.** «Пламя», «Наука», «Детонация» и «Ксенобиология» игра проверяла через Google Play. Сервиса на приставке нет, а сама игра больше не поддерживается, поэтому восстановить покупку оттуда нельзя. Владение записано битовой маской. Биты 0–4 — это набор и четыре пакета. При загрузке профиля к маске добавляются эти биты, и тот же набор поддерживается, пока идёт кадр. Экран модификаций открывается сразу, пакеты показаны как разблокированные. Прогресс миссий остаётся тем, что уже записан в сохранении.

## Сборка

Нужны свой APK, Temurin JDK 17 на машине сборки, Temurin JRE 8 aarch64 только с символами glibc 2.17 и Zig 0.14. JDK, JRE и Zig ставятся отдельно и в репозиторий не входят.

1. `port/tools/gen_stubs.py` строит классы заглушек по APK.
2. `javac --release 8` собирает `port/src` в `shim.jar`. `GoogleApiClient$Builder` переименовывается после компиляции скриптом `rename_builder.py`: исходник с таким именем файла `javac` не принимает.
3. APK превращается в `radiant.jar` через dex2jar. Этот jar остаётся локальным.
4. `port/tools/unlock_premium.py` дописывает в локальный jar включение пакетов при чтении сохранения.
5. Zig собирает `libmojo.so`:

```
zig cc -target aarch64-linux-gnu.2.17 -shared -fPIC -O2 \
  -I <jdk>/include -I port/native/linuxinc -I port/native \
  -o libmojo.so port/native/mojo.c port/native/gles_jni.c port/native/audio.c \
  -lm -ldl -lpthread
```

На карту попадают скрипт из `port/Radiant Defense.sh`, JRE, оба jar, `libmojo.so` и копия APK под именем `game.apk`. Каталог JRE на FAT32 нужно разложить настоящими файлами: одна из библиотек в архиве Temurin — ссылка, а FAT32 ссылки не хранит.

`port/tools/deploy_card.py` копирует собранное на карту, если она смонтирована как `G:`.
